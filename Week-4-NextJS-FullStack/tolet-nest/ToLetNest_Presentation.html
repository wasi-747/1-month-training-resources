THE REAL-WORLD PROBLEM

The Urban To-Let Chaos in Major Cities

Finding student and bachelor accommodation in areas like Bashundhara R/A, Saidnagar, or Dhanmondi is fragmented, stressful, and invasive.

1. Facebook Group Spam

Thousands of unverified, repetitive posts with zero structured search, radius filters, or real-time availability tracking.

2. Hidden Utility Bill Shocks

Listings advertise "৳7,000 Rent" but omit electricity, gas, water, and maid charges, causing unexpected budget explosions.

3. Privacy & Number Leakage

Calling 20 random landlords exposes personal phone numbers and Facebook accounts, leading to persistent unwanted calls.

🎯 Mission: Replace chaotic Facebook To-Let groups with a transparent, structured, privacy-preserving full-stack ecosystem.

CORE INNOVATION

Transparent Rent & Utility Pricing Engine

Eliminates hidden bill surprises by calculating exact total living costs before a tenant schedules a visit.

Mode A: Itemized Breakdown

Specific sub-bills listed: Electricity (৳600), Gas (৳250), Water (৳200), Service Charge (৳250), WiFi (৳150).

Mode B: All-Inclusive Bundle

A single fixed utility surcharge is added to the base rent (e.g. Base ৳6,500 + ৳1,000 all-inclusive = ৳7,500).

Mode C: Contact for Bills

For shared electric meters or flexible student mess meal arrangements.

💡 Transparent UI Badge Formula

Total Monthly Outflow = Base Rent (৳8,500) + Calculated Utilities (৳1,450) = ৳9,950/mo

PRIVACY ARCHITECTURE

In-App Voice Calling & Anti-Harassment Shield

Zero personal phone numbers or social media profiles are exposed during the discovery and negotiation phases.

📞 In-App Voice Call (WebRTC Simulator)

Tenants call landlords directly over the application audio stream. The caller's SIM phone number is never transmitted or visible.

✓ Dial tone, active call timer, mute & speaker controls.

🛑 1-Tap "Close Chat & End Negotiation"

If negotiation fails or terms don't match, the tenant taps "Close Chat". The communication channel is instantly locked on both sides, blocking unwanted follow-up messages or calls.

DATA MODELING

MongoDB Schemas & Spatial Indexing

Robust BSON modeling with pre-save normalization middleware and cached singleton connection pooling.

// Listing Schema (lib/models/Listing.js) const ListingSchema = new mongoose.Schema({ title: { type: String, required: true, trim: true }, rentAmount: { type: Number, required: true, min: 1000 }, area: { type: String, required: true, enum: ['Bashundhara R/A', 'Saidnagar', 'Gulshan', ...] }, location: { type: { type: String, default: 'Point' }, coordinates: { type: [Number], required: true } // [lng, lat] }, utilityInfo: { mode: String, totalUtility: Number, breakdown: Object }, amenities: [String], status: { type: String, enum: ['available', 'visit_scheduled', 'rented'] } });

Key Database Engineering Patterns

  • Global Singleton Pooling: Prevents connection starvation during Next.js dev server hot-reloads.
  • Pre-Save Normalization: Auto-calculates totalUtility on itemized mode.
  • Reactive Hybrid Engine: Auto-falls back to in-memory store if local MongoDB service is offline.
